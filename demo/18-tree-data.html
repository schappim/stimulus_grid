18 — Tree data (self-referential parent_id)

Rows describe a real hierarchy via parent_id (org chart, file tree, BOM, comment thread) — not a group synthesised from a column value. The grid flattens the tree into a display list, draws an indent + chevron on the configured tree column, and routes clicks back through the public gridApi. Filter/sort still apply: search pulls a row's full ancestor chain into view so the path to the match is preserved.

How it's wired: rows carry parent_id → buildTreeDisplayList walks the tree, sorts each sibling group, and emits a flat display list plus a sidecar treeMeta Map (no row mutation). The controller's renderer looks each row up and, when there's a match, prepends an indent + chevron on the tree-display-field column. Cycles and orphans are handled — a row with a missing parent becomes a root.
